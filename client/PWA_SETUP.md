# PWA Setup Documentation for PDFly

This document explains exactly how Progressive Web App (PWA) support was integrated into PDFly. A PWA allows users to "install" the web app on their devices and use it offline, giving it a native app feel.

## Overview of the Integration

The integration was achieved using the `vite-plugin-pwa` library. This plugin automatically generates the Web App Manifest, handles the caching strategies (via Google's Workbox), and injects the Service Worker into the build process.

Here are the exact files that were modified or created to set this up:

---

### 1. Vite Configuration (`client/vite.config.js`)

**Purpose**: This is the core configuration file where the PWA plugin is initialized. It defines the app's metadata (manifest) and tells the service worker what files to cache for offline use.

**Code Used**:
```javascript
import react from '@vitejs/plugin-react'
import { defineConfig } from 'vite'
import tailwindcss from '@tailwindcss/vite'
import { VitePWA } from 'vite-plugin-pwa'

export default defineConfig({
  plugins: [
    react(), 
    tailwindcss(),
    VitePWA({
      registerType: 'autoUpdate', // Automatically update the app when a new version is deployed
      includeAssets: ['favicon.svg', 'icons.svg'], // Static assets to pre-cache
      manifest: {
        name: 'PDFly - Advanced PDF Tools',
        short_name: 'PDFly',
        description: 'Process PDFs directly in your browser',
        theme_color: '#4F46E5', // Indigo color matching the UI
        background_color: '#ffffff',
        display: 'standalone', // Makes the app run in its own window without browser UI
        icons: [
          {
            src: 'pwa-192x192.png',
            sizes: '192x192',
            type: 'image/png'
          },
          {
            src: 'pwa-512x512.png',
            sizes: '512x512',
            type: 'image/png'
          }
        ]
      },
      workbox: {
        // Defines which file types to cache for offline mode
        globPatterns: ['**/*.{js,css,html,ico,png,svg,wasm}'],
        // Increased max size to 5MB because our pdf.worker.js is large
        maximumFileSizeToCacheInBytes: 5000000 
      }
    })
  ],
})
```

---

### 2. Service Worker Registration (`client/src/main.jsx`)

**Purpose**: The service worker needs to be registered when the app loads. We imported the virtual registration module provided by the plugin to handle this seamlessly.

**Code Used**:
```javascript
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import './index.css'
import App from './App.jsx'
// Import the virtual module generated by vite-plugin-pwa
import { registerSW } from 'virtual:pwa-register'

// Execute the registration immediately. 
// Because we set `registerType: 'autoUpdate'` in vite.config.js, 
// this will update the service worker without bothering the user.
registerSW({ immediate: true })

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <App />
  </StrictMode>,
)
```

### 3. HTML Meta Tags (`client/index.html`)

**Purpose**: While the manifest handles standard PWA definitions, Apple devices (iOS) require specific HTML meta tags for the touch icon and theme color to function correctly.

**Code Added**:
```html
<head>
    <meta charset="UTF-8" />
    <link rel="icon" type="image/svg+xml" href="/favicon.svg" />
    
    <!-- Added for iOS Home Screen Icon -->
    <link rel="apple-touch-icon" href="/pwa-192x192.png" />
    
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    
    <!-- Sets the color of the browser address bar / status bar -->
    <meta name="theme-color" content="#4F46E5" />
    
    <meta name="description" content="Process PDFs directly in your browser" />
    <title>PDFly - Advanced PDF Tools</title>
</head>
```

---

### 4. App Icons (`client/public/pwa-192x192.png` & `client/public/pwa-512x512.png`)

**Purpose**: PWAs strictly require square PNG icons in exact sizes (192x192 and 512x512) to be displayed on mobile home screens and desktop taskbars.

**Action Taken**:
We generated a brand new, premium app icon featuring a stylized document in an indigo/violet gradient using AI. This image was then copied directly into the `client/public` directory under the required filenames so the web app manifest could reference them.
